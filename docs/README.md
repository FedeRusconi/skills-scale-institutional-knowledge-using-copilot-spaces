# OctoAcme Project Management Docs

## Overview

OctoAcme uses a structured project management lifecycle to align stakeholders, plan and deliver work, manage risks, communicate progress, and continuously improve how projects are executed.

This repository contains the program process documents that describe the lifecycle, roles, ceremonies, artifacts, quality practices, and escalation paths used across OctoAcme projects.

## Project Management Processes

The OctoAcme project management process follows these stages:

1. **Initiation** — Define the problem, goals, success metrics, stakeholders, timeline, risks, and resource needs. The initiative must pass a decision gate before moving into planning.
2. **Planning** — Turn the approved initiative into an actionable backlog and delivery plan. This includes defining acceptance criteria, estimating work, documenting the Definition of Done, identifying dependencies, and agreeing on milestones.
3. **Execution and tracking** — Deliver work through iterative increments while using project boards, pull requests, CI, testing, demos, status reporting, and blocker escalation to maintain visibility and quality.
4. **Risk management and communication** — Identify, assess, mitigate, and monitor risks and dependencies. Keep stakeholders informed through regular status updates and escalate issues through the defined communication paths.
5. **Release and deployment** — Prepare and deploy completed work using release requirements, staging verification, smoke tests, post-deployment checks, stakeholder announcements, and rollback or incident procedures when needed.
6. **Retrospective and continuous improvement** — Review what went well, identify improvements, assign follow-up actions, and measure the impact of changes after sprints, releases, milestones, or incidents.

Roles and personas provide additional context for how Project Managers, Product Managers, Developers, QA/Testing, and stakeholders contribute throughout the lifecycle.

## How the Documents Fit Together

Start with the [Project Management Overview](docs/octoacme-project-management-overview.md) for the principles, lifecycle, roles, artifacts, and communication cadence used by OctoAcme.

For a new initiative, use the [Project Initiation](docs/octoacme-project-initiation.md) guide to validate the opportunity and authorize planning. Once approved, use [Project Planning](docs/octoacme-project-planning.md) to define the backlog, estimates, milestones, dependencies, risks, and Definition of Done.

During delivery, follow [Execution and Tracking](docs/octoacme-execution-and-tracking.md) for team rhythms, project board usage, pull request practices, quality checks, reporting, metrics, and blocker escalation. Use [Risks and Communication](docs/octoacme-risks-and-communication.md) alongside it to maintain the risk register and provide consistent stakeholder updates.

When work is ready to ship, consult the [Release and Deployment](docs/octoacme-release-and-deployment.md) guide for release types, pre-release requirements, deployment verification, rollback, and incident response.

After each sprint, release, milestone, or incident, use [Retrospective and Continuous Improvement](docs/octoacme-retrospective-and-continuous-improvement.md) to capture learnings and track improvement actions.

Finally, use [Roles and Personas](docs/octoacme-roles-and-personas.md) to clarify responsibilities, goals, and typical communication patterns for the people involved in the project lifecycle.
